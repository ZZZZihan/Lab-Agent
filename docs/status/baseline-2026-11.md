## 2. 实测发现的新问题与注意事项（非阻断，留待后续任务处理）

1. **`init-env.sh` 与 `docker compose up` 的先后顺序（文档与脚本顺序问题）**：
   - T0.1 步骤 1 原文写“先 `docker compose up -d postgres redis`，再执行 `./scripts/init-env.sh`”。但 `docker-compose.yml` 中 `postgres` 依赖 `.env` 里的 `${POSTGRES_PASSWORD}`；若在没有 `.env` 的干净克隆上先起 `postgres`，容器会因为 `POSTGRES_PASSWORD` 为空而初始化失败或与之后 `.env` 生成的随机密码不一致。后续在 `T1.10`（`scripts/demo.sh`）中应确保始终先执行 `./scripts/init-env.sh` 再启动容器。
2. **Magpie 模型命名细微差异**：
   - 规格书 D12 示例列出的 `gpt-oss-120b` 在当前 Magpie `/v1/models` 中的实际 ID 为 `gpt-oss-120b-medium`（及 `antigravity/gpt-oss-120b-medium`），而 `grok-4.7`、`gemini-4-argon`、`gemini-3.8-flash`、`claude-sonnet-5-5` 均原样存在。
3. **Ollama `qwen3-embedding:8b` 默认上下文窗口较大（`40960`）**：
   - `ollama ps` 显示默认加载 `qwen3-embedding:8b` 时分配了 `40960` 上下文，显存占用达 `12 GB`（而模型权重文件本身为 `4.7 GB`），且处理 20000 字长文本单次耗时约 `17s`。这印证了 D13 / `T1.4b` 通过 Modelfile 显式将 `num_ctx` 设为 `8192` 并配合客户端 `EMBEDDING_MAX_INPUT_CHARS` 截断的必要性。
4. **Python 3.14 下的第三方库警告**：
   - 本地 `uv sync` 使用宿主机 CPython `3.14.9` 时，`jieba 0.42.1` 会触发 `SyntaxWarning`（无效转义序列），`langsmith 0.14.17` 会触发 `asyncio.iscoroutinefunction` 的 `DeprecationWarning`（容器内使用 `python:3.12-slim-bookworm` 无此问题）。
5. **项目遗留命名尚未统一**：
   - 数据库用户名、容器内路径、前端会话 Cookie 等仍使用“旧名”，将在 `T0.2`（PR-00b）中集中替换。
